# VPN-пресеты с переносимыми подписками

Установщик для личного VPS: готовая **3x-ui** и **Xray-core**, один из двух пресетов, HTTPS и базовый firewall. Главная гарантия формата: **тот же `instance.json` + тот же домен = та же ссылка подписки**, включая путь и случайный токен.

| Пресет | VPN | Клиент |
|---|---|---|
| `reality` | VLESS + REALITY + XTLS Vision, TCP 443 | актуальный v2rayNG |
| `hysteria2` | Hysteria2 + TLS, UDP 443 | актуальный v2rayNG с поддержкой Hysteria2 |

Один VPS — один пресет. Оба используют Xray; AmneziaWG в эту версию не входит. Подписка выдаётся самой 3x-ui в Base64. Существующий `subs-resolver` получает её URL без изменений своего кода.

## Требования

- Чистая **Ubuntu 24.04 LTS x86_64**, systemd, root/sudo и Python 3.12 из ОС.
- Прямой публичный адрес на сетевом интерфейсе VPS. NAT и CDN-проксирование не поддерживаются.
- Отдельный поддомен; все его A/AAAA должны указывать на эту машину перед выпуском сертификата. Ненужную AAAA-запись нужно удалить.
- На firewall хостинга разрешены текущий SSH-порт, TCP 80, TCP 8443 и TCP 443 (`reality`) либо UDP 443 (`hysteria2`).

Установщик не импортирует чужую установку 3x-ui, существующие сайты Nginx или пользовательские правила UFW. DNS меняется у вашего провайдера вручную. Сам установщик не покупает и не заменяет VPS.

## Первая установка

Скопируйте эту папку или распакуйте архив проекта на VPS. Команды запускаются из папки, содержащей `install.sh`, `versions.json` и `vpn_installer/`:

```bash
sudo bash install.sh --profile reality
```

На втором VPS:

```bash
sudo bash install.sh --profile hysteria2
```

Мастер попросит домен и email для Let's Encrypt. Для REALITY также выбирается целевой TLS-сайт: предложен `www.microsoft.com:443`; доступность, TLS 1.3 и HTTP/2 проверяются с сервера. Доступность этого сайта из вашей сети нужно проверить отдельно.

Для запуска без вопросов:

```bash
sudo bash install.sh --profile reality \
  --domain reality.example.com --email admin@example.com \
  --reality-target www.microsoft.com:443
```

Первый пользователь создаётся автоматически. Адрес панели, пароль администратора и URL подписки выводятся после успешной установки. Остальных пользователей можно добавлять через панель. В первой версии используйте один созданный inbound: базовые параметры транспорта и внешнего адреса обслуживает установщик.

**Сразу сохраните `/etc/vpn-installer/instance.json` вне VPS.** Файл содержит секреты и создаётся с правами `0600`. Не отправляйте его в Git, публичные чаты или трекеры задач. URL подписки также предоставляет доступ к профилям пользователя.

## Перенос без изменения ссылки

На старом VPS сначала экспортируйте актуальные данные, особенно если меняли пользователей через панель:

```bash
sudo bash install.sh --export-config /root/instance.json
```

Перенесите этот файл и установщик на новую машину. Можно подготовить её **до переключения DNS**:

```bash
sudo bash install.sh --config /root/instance.json --prepare
```

Подготовительный запуск устанавливает компоненты и открывает HTTP-проверку сертификата. VPN и HTTPS ещё не готовы. Теперь переключите A/AAAA прежнего домена на новый VPS, дождитесь обновления DNS и завершите установку:

```bash
sudo bash install.sh --config /root/instance.json
```

Переносимый файл сохраняет домен, `:8443`, путь подписки, `subId`, UUID/пароли пользователей, ключи и short ID REALITY, включение и лимиты пользователей. На новой машине создаётся новая БД; старая БД для этого сценария не нужна. TLS-сертификат выпускается заново на тот же домен, привязки к отпечатку сертификата нет.

После обновления DNS существующая группа v2rayNG использует тот же URL. Внешняя ссылка редиректора также не меняется, потому что URL его источников остаются прежними. Во время распространения DNS старый и новый адреса могут временно использоваться разными клиентами; старый сервер лучше оставить доступным до проверки новой машины.

Если потеряны и переносимый файл, и резервная копия, восстановить неизвестные случайные токены невозможно. Сам домен их не определяет.

## Пользователи и повторный запуск

- После первой установки текущие пользователи принадлежат панели. Повторный запуск экспортирует актуальное состояние и **не применяет старый список пользователей поверх нового**.
- `email` пользователя в 3x-ui — идентификатор; реальный почтовый ящик для него не требуется. Верхний `email` файла нужен Certbot.
- `total_gb` сохраняет название поля 3x-ui, но значение задано **в байтах**; `expiry_time` — Unix-время в миллисекундах. Ноль означает отсутствие соответствующего ограничения.
- `limit_ip` переносится как настройка панели; применение ограничения числа IP требует отдельно настроенного fail2ban. В установке v1 он не включён, значение по умолчанию — `0`.
- После добавления, удаления, отключения пользователя или изменения его ключей обновите внешнюю копию через `--export-config`.
- Дополнительные inbounds, hosts, внешние ссылки, автоматические сбросы лимитов, HWID и другие настройки вне двух базовых пресетов не входят в переносимый формат v1. Экспорт откажется от неподдерживаемых изменений, которые умеет обнаружить. Для произвольной настройки используйте полную резервную копию БД, не полагайтесь на переносимый файл.
- Если сменили логин или пароль администратора, обновите `panel.username`/`panel.password` в защищённом `/etc/vpn-installer/instance.json`: API не возвращает пароль в открытом виде. Смена путей панели или подписки вручную требует согласованной перенастройки Nginx, поэтому такие изменения следует делать через перенос на чистый VPS.

Проверка файла без изменения системы (можно на локальном компьютере с Python 3.10+ и OpenSSL):

```bash
bash install.sh --check-config ./instance.json
```

Неполный файл не дополняется новыми случайными ключами. Проверка завершается до установки пакетов и изменений firewall.

## HTTPS и безопасность

| Снаружи | Назначение |
|---|---|
| Текущие SSH-порты | Существующий доступ к серверу |
| TCP 80 | Только `/.well-known/acme-challenge/` |
| TCP 8443 | HTTPS панели и подписок |
| TCP 443 или UDP 443 | Выбранный VPN |

Внутренние порты 2053 и 2096 слушают localhost после настройки. Nginx маршрутизирует панель и подписки раздельно, сохраняя путь запроса. Access logs выключены; error logs этих виртуальных серверов также не записывают URL с токенами. При первичном запуске панели внешний доступ к её внутренним портам уже блокируется UFW.

Certbot единолично управляет сертификатом. `certbot.timer` продлевает его автоматически; deploy hook обновляет Nginx и для Hysteria2 перезапускает `x-ui`, что кратко прерывает соединения. Встроенный выпуск сертификатов панели включать не нужно.

UFW закрывает остальные входящие подключения для IPv4 и IPv6. Текущие SSH-порты разрешаются до включения firewall; SSH-аутентификация не меняется. Повторный запуск не удаляет правила, которые вы добавили вручную.

## Проверка, резервные копии и обновление

```bash
sudo bash install.sh --status
sudo bash install.sh --backup
```

Полная копия создаётся в `/etc/vpn-installer/backups/` с правами `0600`: согласованный SQLite-снимок БД с историей и счётчиками, переносимый файл и маркер установки. Для обычного переноса используется JSON; автоматическое восстановление полной БД в этом интерфейсе не реализовано.

Версии и SHA-256 официальных архивов находятся в `versions.json`. Установка не выполняет плавающие удалённые install-скрипты. Обычный повторный запуск не обновляет бинарники. После изменения и проверки закреплённых версий обновление выполняется явно:

```bash
sudo bash install.sh --update
```

Перед обновлением создаётся резервная копия; на время проверки сохраняются прежние бинарники и снимок БД. При ошибке запуска выполняется откат. Обновление через интерфейс самой 3x-ui обходит эти проверки, поэтому для воспроизводимости используйте установщик.

Проверка продления на VPS:

```bash
sudo certbot renew --dry-run
```

Без `--run-deploy-hooks` эта команда проверяет ACME, но не запускает наш deploy hook. Обработчик продления отдельно проверяется автоматическими тестами; для полной приёмки нужен реальный выпуск/продление и проверка подключения.

## Проверки проекта

```bash
python3 -m unittest discover -s tests -v
```

Реальная интеграционная проверка запускается отдельно в изолированном Ubuntu-контейнере, без изменения сервисов или firewall хоста:

```bash
bash tests/run-integration.sh /tmp/self-variants-artifacts
```

Каталог содержит официальные `x-ui-linux-amd64.tar.gz` и `Xray-linux-64.zip` из закреплённых релизов. Их SHA-256 указаны в `versions.json`. Подробные действия сценария находятся в `tests/integration.py`.

Контейнерные проверки не заменяют приёмку на VPS: реальный ACME, загрузка systemd после перезагрузки, внешний firewall, Android v2rayNG и доступность из РФ проверяются на развёрнутых серверах. Текущий редиректор проверяет доступность HTTP-подписки, а не VPN-соединения; несколько протоколов не гарантируют защиту IP от блокировки.

## Структура

- `install.sh`, `vpn_installer/cli.py` — команды и этапы установки.
- `config.py` — переносимый формат и сохранение идентификаторов.
- `panel.py` — API закреплённой версии 3x-ui и два VPN-пресета.
- `system.py` — проверки машины, архивы, systemd и резервные копии.
- `network.py` — Nginx, Certbot и UFW.
- `versions.json` — версии и контрольные суммы.

Справочные копии старых скриптов в `x-ui-pro-review/` не используются установщиком.

Официальные источники: [3x-ui 3.11.0](https://github.com/MHSanaei/3x-ui/releases/tag/v3.11.0), [Xray 26.11.9](https://github.com/XTLS/Xray-core/releases/tag/v26.11.9), [протоколы 3x-ui](https://github.com/MHSanaei/3x-ui/blob/v3.11.0/docs/content/docs/en/config/inbounds.mdx), [Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html).
